# خطة إدارة تراخيص حقيبة المدرس

## النتيجة المستهدفة

تظهر بوابة التفعيل قبل أي شاشة أخرى عند أول تشغيل على جهاز جديد:

```text
فتح التطبيق
  -> إدخال رمز تفعيل صالح / بدء تجربة مجانية 3 أيام
  -> استعادة جلسة حساب موجودة أو شاشة الدخول الحالية (جوجل / فيسبوك / ضيف)
  -> التطبيق
```

شاشة الحساب تبقى بعد التفعيل فقط عندما لا توجد جلسة سابقة؛ فهي مطلوبة في النسخة الحالية للمزامنة السحابية. لا تحتوي بوابة الترخيص على شراء أو دفع أو رابط خارجي.

## قواعد العمل

| البند                     | السياسة المطبقة                                               |
| ------------------------- | ------------------------------------------------------------- |
| التجربة المجانية          | 3 أيام من وقت خادم Supabase، مرة واحدة لمعرف تثبيت التطبيق    |
| نوع الترخيص               | شهر، 3 أشهر، سنة، أو تاريخ يدوي/دائم يحدده المالك             |
| الأجهزة                   | جهاز واحد افتراضياً، والمالك يضبط من 1 إلى 50 لكل رمز         |
| حالات الرمز               | نشط، موقوف مؤقتاً، ملغى                                       |
| الرمز غير الصحيح          | رسالة عربية واضحة ولا يُمسح ما كتبه المستخدم                  |
| انقطاع الإنترنت           | يحتفظ التطبيق بآخر تحقق ناجح: 24 ساعة للتجربة و7 أيام للترخيص |
| انتهاء التجربة أو الترخيص | يمنع الانتقال إلى التطبيق ويعرض بوابة التفعيل فقط             |

### رسائل المستخدم

- الرمز غير الصحيح: `رمز التفعيل غير صحيح، يرجى التأكد من الرمز والمحاولة مرة أخرى.`
- انتهاء الترخيص: `انتهت صلاحية هذا الترخيص.`
- انتهاء التجربة: `انتهت الفترة التجريبية. أدخل رمز التفعيل للاستمرار في استخدام حقيبة المدرس.`
- تعذر الاتصال: `تعذر الاتصال بخدمة التفعيل مؤقتاً. تحقق من اتصالك ثم أعد المحاولة.`
- التجربة النشطة: `متبقي يومان من الفترة التجريبية` أو `تنتهي تجربتك المجانية اليوم`.

## ما نُفذ في المشروع

### تطبيق المستخدم

- `src/features/license/LicenseScreen.tsx`: شاشة RTL عربية مطابقة للترتيب المطلوب.
- `src/features/license/licenseStore.ts`: بوابة حالة تمنع التنقل قبل قرار الترخيص.
- `src/services/licenseService.ts`: معرف تثبيت عشوائي، التخزين المؤقت، واستدعاء الخدمة الخلفية.
- `src/features/license/TrialStatusBanner.tsx`: شريط متبقّي التجربة في الصفحة الرئيسية والإعدادات.
- `RootNavigator`: يفحص الترخيص بالتوازي مع استعادة جلسة المستخدم، ويعرض شاشة الترخيص أولاً عند الحاجة.

### الخلفية

- `supabase/migrations/20260902_license_management.sql`: جداول التراخيص والتفعيلات والتجارب والمراجعة وحدود الطلبات.
- `supabase/migrations/20260903_license_management_hardening.sql`: حماية لاحقة لحد الطلبات، حد الأجهزة، الإلغاء، وتسلسل التفعيل للجهاز نفسه.
- `supabase/migrations/20260904_license_code_recovery.sql`: حقل مشفّر لاسترجاع رموز التفعيل الجديدة من تطبيق المالك.
- `supabase/functions/licenses/index.ts`: نقطة خلفية واحدة للتحقق، بدء التجربة، التفعيل، وإدارة المالك.
- لا يُخزّن رمز التفعيل خاماً: تحتفظ قاعدة البيانات ببصمة SHA-256 للتفعيل ونسخة AES-GCM مشفّرة للاسترجاع من حساب مالك مخوّل فقط.
- تفعيلات الترخيص تتم داخل دالة PostgreSQL ذرية مع قفل صف الترخيص، لمنع تجاوز حد الأجهزة بطلبات متزامنة.

### لوحة المالك

المجلد `license-admin/` هو تطبيق ويب RTL مستقل. يدعم:

- الدخول بواسطة Google.
- إنشاء رمز باشتراك شهر أو 3 أشهر أو سنة، أو تاريخ يدوي/دائم، مع عدد أجهزة وملاحظة داخلية.
- عرض رمز أي ترخيص جديد ونسخه عند فتح تفاصيله.
- البحث بالاسم أو الرمز الكامل.
- إيقاف أو إلغاء أو إعادة تنشيط الترخيص وتغيير تاريخ الانتهاء وحد الأجهزة.
- عرض الأجهزة المفعلة وإلغاء تفعيل جهاز مفرد.
- ملخص التراخيص والتجارب والأجهزة النشطة.

لا تحتوي اللوحة على `service_role` أو أي سر. صلاحياتها تُتحقق داخل Edge Function بعد فحص حساب Supabase في جدول `license_admins`.

## نموذج البيانات

| الجدول                | الغرض                                                                   |
| --------------------- | ----------------------------------------------------------------------- |
| `licenses`            | بصمة الرمز ونسخته المشفّرة، حالته، انتهاءه، حد الأجهزة، وملاحظات المالك |
| `license_activations` | ربط الرمز بمعرف تثبيت الجهاز، المنصة، وآخر تحقق                         |
| `license_trials`      | بداية ونهاية التجربة أو علامة استهلاكها لكل تثبيت                       |
| `license_admins`      | قائمة حسابات المالك أو الموظفين المخولين فقط                            |
| `license_audit_log`   | من أنشأ أو عدّل أو ألغى تفعيلًا                                         |
| `license_request_log` | بصمة مملحة مؤقتة لحد محاولات التخمين، بلا رمز أو عنوان IP خام           |

## الأمان والحدود الواقعية

- جداول الترخيص محمية بـ RLS ولا تمنح `anon` أو `authenticated` وصولاً مباشراً.
- دالة Edge فقط تستخدم `service_role`، وتتحقق يدوياً من JWT وصلاحية المالك للعمليات الإدارية.
- جميع الاتصالات تستخدم HTTPS من Supabase.
- لا تسجل الدالة محتوى طلب التفعيل، حتى لا يظهر الرمز في السجلات.
- لا يسجل سجل التدقيق قيمة الرمز عند عرضه؛ يسجل حدث العرض فقط. لا تغيّر `LICENSE_CODE_ENCRYPTION_KEY` بعد إنشاء الرموز، وإلا لن يمكن استرجاع النسخ المشفّرة السابقة.
- يوجد حد للمحاولات لكل شبكة لتقليل تخمين الرموز، مع حفظ بصمة مملحة فقط بدلاً من عنوان IP الخام.
- تحفظ فترة السماح وفق وقت الخادم وتكتشف حالات واضحة من إعادة ساعة الجهاز للخلف، لكنها لا تمنع التحايل على الوقت دون اتصال بشكل كامل ولا تُعد بديلاً عن حماية عتادية.
- احذف سجلات `license_request_log` الأقدم من 30 يوماً عبر مهمة مجدولة.
- لا تضع `service_role` أبداً في التطبيق أو لوحة الويب. إذا كان أي مفتاح خدمة قد ظهر خارج بيئة آمنة، بدّله قبل النشر.

معرف التثبيت يبقى عند استخدام خيار إعادة التعيين داخل التطبيق، لكنه لا يستطيع وحده منع تجربة جديدة بعد مسح بيانات التطبيق من نظام التشغيل أو حذفه وإعادة تثبيته أو على جهاز جديد. الحماية الأقوى في مرحلة لاحقة هي ربط الترخيص بحساب Google إلزامي، وتطبيق Play Integrity على Android، ثم التحقق من سلامة الجهاز في Edge Function. لا تستخدم بصمة جهاز خفية لأنها غير موثوقة وغير مناسبة للخصوصية.

عند خفض حد الأجهزة من اللوحة، ألغِ تفعيل الأجهزة الزائدة أولاً. يمنع النظام خفض الحد إذا كان عدد التفعيلات النشطة أكبر من الحد الجديد.

## خطوات النشر

نفّذ هذه الخطوات بالترتيب، ولا تنشر نسخة التطبيق التي تتضمن شاشة الترخيص قبل نجاح الخطوات 1 إلى 7.

1. من Supabase SQL Editor شغّل بالترتيب `supabase/migrations/20260902_license_management.sql` ثم `supabase/migrations/20260903_license_management_hardening.sql` ثم `supabase/migrations/20260904_license_code_recovery.sql`.
2. في إعدادات Google Cloud OAuth أضف Redirect URI الخاص بـ Supabase:

```text
https://YOUR_PROJECT_REF.supabase.co/auth/v1/callback
```

3. في Supabase Authentication أضف إلى Redirect URLs:

```text
    http://localhost:5175/
    https://your-license-admin-domain.example/
    teacherbagadmin://auth-callback
```

4. أنشئ قيمتين عشوائيتين قويتين (32 حرفاً على الأقل) لـ `LICENSE_RATE_LIMIT_SALT` و`LICENSE_CODE_ENCRYPTION_KEY` ثم خزّنهما كأسرار في Supabase. احتفظ بمفتاح التشفير نفسه ما دامت هناك رموز تريد استرجاعها:

```bash
npx supabase secrets set LICENSE_RATE_LIMIT_SALT="ضع-قيمة-عشوائية-طويلة" LICENSE_CODE_ENCRYPTION_KEY="ضع-مفتاح-تشفير-عشوائي-طويل" --project-ref YOUR_PROJECT_REF
```

5. انشر دالة التراخيص مع تعطيل تحقق البوابة الافتراضي، لأن المستخدم غير المسجل يحتاج لبدء تجربة أو إدخال رمز. الدالة تتحقق بنفسها من صلاحية المالك:

```bash
npx supabase functions deploy licenses --no-verify-jwt --use-api --project-ref YOUR_PROJECT_REF
```

6. أنشئ `license-admin/.env.local` وضع عنوان Supabase والمفتاح القابل للنشر فقط. Vite يضم هذه القيم وقت البناء، لذلك أعد تشغيله أو ابنِ اللوحة مجدداً بعد تعديلها:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

ثم شغّل اللوحة وسجّل الدخول مرة واحدة بحساب Google الذي سيصبح مالكاً:

```bash
npm run license-admin
```

7. من SQL Editor أضف الحساب الذي سجّل دخوله إلى دور المالك، ثم أعد تحميل اللوحة:

```sql
insert into public.license_admins (user_id)
select id from auth.users where lower(email) = lower('owner@example.com')
on conflict (user_id) do nothing;
```

8. ابنِ اللوحة ثم استضف محتوى `dist-license-admin/` على نطاق HTTPS خاص بالمالك، ثم أضف نطاقه إلى Redirect URLs أعلاه:

```bash
npm run license-admin:build
```

9. أنشئ رمزاً اختبارياً من اللوحة، واختبره على نسخة تطوير، ثم ابنِ نسخة التطبيق.

## حالات القبول قبل الإصدار

1. تثبيت جديد متصل: تظهر بوابة التفعيل فقط.
2. رمز صحيح دائم: يفتح التطبيق ولا تظهر البوابة في الفتحات التالية.
3. رمز بتاريخ ماضٍ: تظهر رسالة انتهاء الصلاحية ولا يفتح التطبيق.
4. رمز غير صحيح: تظهر الرسالة المطلوبة ويبقى النص في الحقل.
5. تجربة مجانية: تفتح التطبيق ويظهر الشريط بحالة الأيام المتبقية.
6. تجربة انتهت: يعيد الفتح إلى بوابة التفعيل ولا يظهر زر تجربة جديد.
7. إلغاء جهاز من اللوحة: يمنع الجهاز عند التحقق التالي أو بعد انتهاء فترة السماح المحلية.
8. إيقاف الرمز من اللوحة: يمنع كل الأجهزة المرتبطة عند التحقق التالي.
9. إلغاء جهاز ثم فتح بوابة الترخيص: لا يمكنه بدء تجربة مجانية جديدة.
10. انتهاء تجربة أو ترخيص والتطبيق مفتوح: ينتقل إلى بوابة التفعيل عند الوقت المحدد.
11. انقطاع الاتصال بعد تحقق صالح: يستمر الوصول خلال فترة السماح فقط.
12. حساب Google غير مضاف إلى `license_admins`: لا يرى أو يعدل أي بيانات ترخيص.
13. رمز جديد: يظهر عند فتح تفاصيل الترخيص ويمكن نسخه؛ أما رمز قديم أُنشئ قبل ترحيل الاسترجاع فيظهر أنه غير قابل للاسترجاع.

## تطبيق أدمن Android مستقل

يبني المشروع تطبيق مالك منفصلاً بحزمة `com.teacherbag.admin`؛ يمكن تثبيته بجانب
تطبيق حقيبة المدرس ولا يحتوي على أي مفتاح خدمة. أضف
`teacherbagadmin://auth-callback` إلى Redirect URLs في Supabase قبل تسجيل الدخول
منه، ثم ابنِه بالأوامر التالية:

```bash
npm run apk:admin-android
npm run bundle:admin-android
```

مخرجات البناء هي `android/app/build/outputs/apk/admin/app-admin.apk` و
`android/app/build/outputs/bundle/admin/app-admin.aab`.
